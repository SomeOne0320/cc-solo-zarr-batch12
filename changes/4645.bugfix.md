Speed up `nchunks_initialized` and `_nshards_initialized` for sparse arrays. The number of stored chunks (or shards) is now determined by decoding the keys returned from the store, instead of enumerating every coordinate in the logical chunk grid. This keeps counting costs proportional to the number of stored keys even when the logical array is enormous. Keys from prefix-similar siblings, array metadata, keys outside the current shape, and keys that merely resemble chunk keys are not counted. Custom chunk key encodings that cannot decode keys fall back to the previous behavior.
