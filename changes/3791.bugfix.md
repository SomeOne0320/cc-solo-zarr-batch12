Fixed ``AsyncArray.append`` and ``Array.append`` so that invalid input is rejected before
the array is modified. Previously, data that could not be cast to the array's dtype (for
example strings that cannot be parsed as integers) raised during encoding, but only after
the array metadata had already been resized, leaving the array longer than the amount of
written data and filled with fill values. Appends now validate the axis (including
NumPy-style negative indices), the number of dimensions, the non-append axis lengths and
the dtype conversion up front, so a failed append leaves both the live object and a
reopened array unchanged and the next valid append continues from the original end.
